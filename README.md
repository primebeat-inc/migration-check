# サイトとメールの引っ越し判定

今のレンタルサーバーから、サイトとメールを移せるかを無料で判定するツールです。サイトの移し先は Cloudflare、メールの移し先は Google Workspace などを考えています。URL を入れると、Cloudflare に移せるか、メールの置き場所、サイトの作り、管理画面が外から開けるかが分かり、持ち主がやる手順が出ます。

公開版: https://check.prime-beat.com （ベータ版。運営は Prime Beat株式会社）

## 運営会社を信頼しなくても確かめられるように作っています

| 判定の部分 | 動く場所 | 届く先 |
|---|---|---|
| DNS・メール・SPF・DKIM・DMARC | 利用者のブラウザ（`public/lib/dns-checks.js`） | Cloudflare の公開 DNS（cloudflare-dns.com） |
| ドメインの登録事業者と移管のロック | 利用者のブラウザ（同上） | IANA と、そのドメインの登録所の RDAP。.jp は問い合わせない |
| 判定の規則（型と手順を決める部分） | 利用者のブラウザ（`public/lib/verdict.js`） | どこにも送らない |
| サイトの中身（CMS・PHP の版・管理画面） | 運営のサーバー（`src/site-checks.js`、Cloudflare Workers） | 運営のサーバーにドメインが届く。サーバーはそのサイトに最大5回アクセスする |

サイトの中身だけはサーバーで読みます。ブラウザは CORS の決まりで、他のサイトの HTML とヘッダーを読めないためです。この部分は、サーバーで動くコードを信頼するか、自分で動かす（下の「手元で動かす」）必要があります。

確かめる方法は3つあります。

1. **配られているファイルを見比べる。** 画面の下に、いま動いている版のコミットが出ます。リポジトリを手元に取ってきて次を実行すると、公開版が配っている画面のファイル（`public/` の中身）と、そのコミットのファイルをハッシュで見比べます

   ```bash
   npm run verify
   ```

2. **通信を見る。** ブラウザの開発者ツールのネットワーク欄で、どこに何を送っているかを見られます。運営のサーバーに届くのは `/api/site?host=<ドメイン>`（サイトの中身の判定）と `/api/event`（件数）だけです
3. **全部を手元で動かす。** 運営のサーバーを使わずに、同じ判定を手元のパソコンで動かせます

サーバーで動いているコードが公開のものと同じことは、Cloudflare Workers の仕組みの上では証明できません。そのため、サーバーに任せる部分をサイトの中身の読み取りだけにしています。

## 手元で動かす

Node.js 22 以上。

```bash
npm install
npm test
npm run check -- example.co.jp
```

`npm run check` は、判定のすべて（DNS とサイトの中身）を手元のパソコンから行い、結果を JSON で出します。運営のサーバーは使いません。

画面ごと手元で動かすときは次のコマンドで、http://localhost:8790/ を開きます。

```bash
npm run dev
```

## 自分の Cloudflare で動かす

`wrangler.jsonc` の `routes` を自分のドメインに書き換えて、`npx wrangler deploy` を実行します。Durable Objects は SQLite を使う型なので、Workers の Free プランでも動きます。件数を見たいときは `npx wrangler secret put STATS_TOKEN` で合言葉を入れ、`STATS_URL=<公開先> npm run stats` で見ます。合言葉を入れなければ件数の画面は 404 を返します。

## 調べること

| 調べること | 使うもの |
|---|---|
| Cloudflare に移管できるか | ドメインの末尾と、Cloudflare の TLD Policies から取り出した一覧（`public/lib/tlds.js`、取り出した日を書いてある）。.jp は移管できない |
| DNS の置き場所、すでに Cloudflare か | NS |
| 登録事業者、登録日、移管のロック | IANA の一覧から引いた登録所の RDAP |
| メールの置き場所 | MX と、MX の IP がサイトと同じか |
| SPF・DKIM・DMARC | TXT。DKIM はよく使われるセレクタ（google、selector1、selector2、default、k1）だけを見る |
| サイトの作り | トップページへの GET 1回。CMS とサイト作成サービスの目印、サーバーで動くプログラムの目印（PHP のヘッダー、セッションの Cookie、`.php` などへのリンク） |
| PHP の版 | 応答のヘッダー。JPCERT/CC の注意喚起 JPCERT-AT-2026-0033 の修正版と比べる |
| 管理画面が外から開けるか | `/wp-login.php`・`/wp-admin/`（WordPress のときだけ）、`/administrator/`、`/admin/` への GET。パスワードの入力欄があれば「公開」 |

## 判定の型

| 型 | 条件 |
|---|---|
| 型A: 静的サイトの可能性 | どの目印も無い |
| 型B: CMS の名前 | CMS の目印がある |
| 型C: サイト作成サービス | Wix・Shopify などの目印がある。ネームサーバーを変えられないことが多く、移行の対象外 |
| 型を確かめる必要がある | CMS の目印は無いが、サーバーで動くプログラムの目印がある |
| 型を判定できない | ボット対策の確認画面やエラーで中身を読めない（確認画面は突破しない） |
| すでに Cloudflare に移っている | DNS もサイトも Cloudflare |

判定の規則は `tests/` のテストで確かめられます。

## 公開版の守り

| 守り | 中身 |
|---|---|
| 接続元ごとの回数 | 1分に10回まで。接続元ごとに Durable Object を1つ割り当て、直近60秒の回数をメモリで数える（IPv6 は /64 単位） |
| 同じドメインへの回数 | 1分に6回まで（Workers の Rate Limiting） |
| 結果の使い回し | 同じドメインのサイトの結果を10分使い回す |
| 調べられる側への配慮 | User-Agent に `PrimeBeat-migration-check` とこのリポジトリの URL を入れる |
| 手元や社内の機械を指す入力 | IP の直書き、localhost などの名前、私用の IP に解決される名前、私用の IP へのリダイレクトを断る |
| 画面 | スクリプトは同じ場所のファイルだけを読む CSP。`frame-ancestors 'none'`、`nosniff`、`no-referrer` |

## 数えているもの

日ごとの件数だけです。判定の型、メールの引っ越しが要ったか、相談のリンクが押されたか。ドメインと接続元は含みません（`src/stats.js`）。

## 分かっている限界

- 外から見える情報だけで判定するので、間違えることがあります。「気をつける点」が無くても、安全という意味ではありません
- メールの置き場所は事業者の名前の一覧で見分けます。一覧に無い事業者と自前のメールサーバーは「見分けられない」になります
- サブドメインと、MX・TXT 以外の DNS の設定は外から一覧できません
- 同じドメインへの回数の制限は近似です
